# UI 架构：围绕自动化任务

状态：2026-10-06。当前使用通用任务编辑、当前托盘多选面板、进程组、Steam 启动同步工具、融合标题栏、可编辑快捷键与系统/浅色/深色主题。当前验证范围以交接页为准。

## 信息架构

```text
Axiom
├─ 自动化（默认首页）
│  ├─ 我的规则：名称 / 条件 → 动作 / 已启用或已暂停
│  ├─ 新建自动化 → 何时执行 → 执行什么 → 结束与冲突 → 保存
│  └─ 编辑自动化 → 保存 / 取消 / 删除
├─ 组：组类型入口 → 进程组的创建 / 编辑 / 删除 → 批量输入弹窗或程序文件选择
├─ 工具箱：Steam 自动整理开关 / 检查更新 → 工具设置弹窗 → 名单搜索 / 勾选或批量排除 / 保存
├─ 活动记录：按日期分组 / 检测、执行、异常及配置记录 / 较新与更早分页 / 清除七天前记录
└─ 设置：外观主题 / 全局快捷键 / 关闭窗口的行为 / 登录启动开关与位置更新 / 停止后台并退出
```

不再设总览大屏、能力展板、规划中卡片、开发验收说明。首页最重要的是用户已保存的规则和“新建自动化”；后台状态降为辅助信息，最新活动摘要放在列表之后，链接到活动记录。活动记录只展示真实保存的事件，不根据全局状态为每条规则编造执行记录。

## 核心交互

1. 列表以规则名称为一级、条件和动作为二级、退出策略和启用状态为辅助。编辑与暂停位于对应规则，不显示数据库版本、能力 ID 或内部状态码。
2. 新建/编辑进入独立页面：名称 → 检测什么（类型、参数）→ 执行什么（类型、参数）→ 运行方式。检测和动作是独立类别，即使当前各只有一种，也保留类型选择。目录、分类、字段、资源选项与行为说明由后台注册提供；UI 不按能力 ID 写专用分支。新任务不替用户默认选中 HDR。只提供已接通且兼容的组合，不陈列空能力。
3. 保存等待后台确认，成功才回到列表并提示“已保存”。正在请求时禁用重复提交；失败保留输入。版本冲突允许显式重新读取已保存版本，先确认放弃输入；不自动覆盖新版。
4. 取消、切页、关闭窗口时，存在未保存更改先确认。刷新不能抹掉编辑内容或悄悄升级待提交版本。目标显示器暂不可用时保留原选择，不自动换到另一台。
5. 启用是允许检测，不表示正在执行。执行与退出语义、编辑警告由动作声明提供。HDR 适配器须明确运行中暂停/删除/修改会让出本轮控制，保留物理状态，本次退出不再恢复；不能把这条行为推广到所有动作。
6. 关闭窗口只退出 UI；设置内显式停止后台需确认。宿主拒绝停止时说明先正常退出游戏并等待恢复，不强杀后台绕过。
7. 登录启动设置由宿主读写当前用户最高权限的登录计划任务，只有布尔开关，UI 不发送可执行路径。启用后只启动管理员后台，不保存密码；“已登记”不等于已运行。读回未确认时禁用开关并明确状态未知，保存失败显示原因。登记指向其他文件夹时提供“更新启动位置”；提醒 Windows 可延迟启动、删除程序前关闭登记。旧 HKCU Run 启用项由管理员 Host 迁移，关闭状态不新增登记。关闭登录启动不影响当前运行中的任务。
8. 全局快捷键置于设置页顶部，支持新增、编辑、启停、删除；功能选择来自已接通功能目录，当前只有显示 / 关闭 Axiom 窗口，同一组合切换开关，关闭后任务栏按钮消失、后台继续。编辑用功能选择、修饰键和按键；保存等待真实注册和持久化确认。冲突保留输入和旧组合，回复未确认时禁用重复保存并提示取消后刷新。已生效、已停用、未生效及原因分别显示；关闭 UI 后继续监听，停止后台后释放。快捷键不补发旧按键。
9. 外观位于设置页最上方，提供跟随系统 / 浅色 / 深色；首次默认跟随系统。选中后先保存再即时应用，失败保留原选择并说明原因。只更新颜色，不重建编辑表单、不重启后台。主题是 UI 本地偏好，文件 `%USERPROFILE%\.axiom\ui-theme.txt` 以临时文件替换保存；规则、快捷键和登录启动的宿主写入边界不变。
10. 活动记录按日期分组，最新在前，每页按当前窗口可视空间读取合适数量，通过“较新记录 / 更早记录”访问全部保留历史；不一次加载全库。每行突出发生的事，随后显示相关任务/程序（有则显示）、原因、绝对时间与类别，以简洁图标辅助区分完成/提醒/异常。分页返回页首，窗口尺寸变化时回到最新页并重新估算容量；不自动轮询或把刷新记为活动。
11. “清除 7 天前的记录”一键执行，无二次确认；后台以执行时刻 UTC 减七天为界，仅删除严格早于界限的记录，保留边界及之后的活动。事务操作确认后显示删除数量并重新读取最新页；失败/回复丢失不得假报成功，旧内容保留并说明未确认。日志读取/写入异常独立提示，不把日志正常等同于自动化执行正常。
12. 检测字段可声明 `ProcessSelection`：保留所有已保存进程，提供逐项移除、从组勾选/全选/取消组内选择、“批量输入名单…”弹窗及批量选择 exe。多行输入只存在于应用内 ContentDialog，先验证全部名称及数量，确认才加入；取消不改变已有名单，不在表单常驻大输入框。自动化列表只显示检测类型，具体进程名单在编辑页查看，不重复展示“检测的程序：xxx”。名字按大小写不敏感去重，任务和每组上限 128；选入规则后名单独立保存，修改/删除组不改运行中的任务。HDR 与插件适配器各自仍限制最多 128 个不同目标，不能通过增加组绕过。
13. 进程组通过同用户 Host 管道保存到 SQLite，命名、版本冲突、成功/失败及未保存退出保护与任务一致。最多 32 组、合计 512 个程序，另有 IPC 内容大小限制；空组允许暂存。UI 不直接访问组数据库或注册表。
14. “组”首页按组类型展示入口，当前仅有真实可用的进程组；“工具箱”首页按工具展示入口，当前仅有 Steam 游戏自动整理。统一图标、标题、说明和进入按钮，后续新增类型/工具可追加入口，不为预留扩展显示空能力。进程组列表在“管理进程组”内，不和类型首页混排。“本机上的Steam游戏”由工具维护，卡片提供“工具设置”而非手工编辑/删除；关闭工具保留组。
15. Steam 卡片提供持久化“每次启动自动更新”开关、工具设置和立即检查更新。默认关闭，首次开启立即同步；开启后每次 Host 启动扫描，不依赖 UI，窗口重开不扫描。仅通过 Steam 元数据更新固定“本机上的Steam游戏”，不再选择导入目的组；完整新名单替换旧名单，扫描失败或库不可用保留原组，组变化不暗改已有规则。工具设置 ContentDialog 显示上次结果、时间、警告、当前名单和长期排除项，搜索/虚拟列表只在弹窗，主工具箱不铺结果。勾选表示排除，支持批量勾选/取消和“批量添加排除项…”；未检测到的排除名仍保留。批量输入每行一个 exe 文件名，验证全部后加入草稿，顺序关闭/重开对话框，取消不修改保存状态；保存以打开时版本校验。安装清单没有 exe，另用 appinfo Windows 启动配置核对具体文件；无法识别时说明原因，不猜 exe，启动器可能不同于真实游戏进程。超过组容量时明确提示调整排除，不能截断假报成功。关闭开关停止自动导出；关闭时手动检查仅更新工具结果。主窗关闭时若有弹窗，先关闭弹窗，再遵守页面未保存保护。
16. 检测目录中的“Axiom 启动时”使用普通 Choice 字段“启动次数”：默认每次启动时，可选本次开机首次启动时；支持启动/关闭程序及关闭窗口，动作字段保留延迟等各自声明的选项。启动指后台启动并准备好执行动作，窗口重开不触发；新建/编辑/启用从下一次后台启动生效。首次是本次开机第一次后台启动，错过首次、失败或取消不补执行；文案与活动明确这些区别，不把已启用写成已执行。
17. “关闭窗口”是窗口类别的独立动作，等待窗口与动作延迟分别解释；每次为每个目标关闭一个主窗口、之后手动打开不干预。编辑提示说明模拟点击 ×，目标软件决定留在托盘还是退出；不把该动作写成强制结束进程，也不承诺任意 GUI 软件都可留在后台。
18. “关闭窗口”“关闭程序”的目标声明 `ExecutableSelection`，复用紧凑名单、逐项移除、“批量输入名单…”应用内弹窗和程序文件多选。每行一个本机完整 exe 路径，大小写不敏感去重，最多 32 个；弹窗一次验证全部，错误保留弹窗与输入，取消不改名单。旧单路径原样读回，不强制迁移或改规则。动作按完整路径匹配，不能直接使用只有文件名的进程组；相似可多对象场景优先多选。文件/目录选择使用已有 Windows App SDK 1.8 的 `Microsoft.Windows.Storage.Pickers`、关联 AppWindow.Id，兼容管理员界面；没有能力 ID 专用分支。
19. “托盘 / 隐藏托盘图标”声明 `TraySelection`，提供“从当前托盘选择…”应用内面板、搜索、刷新、结果全选/取消及逐项勾选；仍可手动批量输入或多选 exe。面板读取当前可识别图标（含折叠区），同一实际 exe 合并并显示图标数和完整路径；不列历史/已移除图标，不能识别不冒充可操作。打开/主动刷新才读取并显示时间，无周期轮询；刷新保留勾选草稿，取消不提交，确认存完整路径，不保存瞬态图标编号；旧名单中暂时没图标的目标保留，仍限制 32 个。参数提供等待图标与延迟执行；一次触发处理当前可识别图标，保留后台进程，软件/资源管理器重建后可能再出现，暂停不恢复，可重新打开或重启目标软件恢复。提醒托盘菜单/气泡通知可能不可用及版本识别限制；结果未确认不写成功，不提供无效恢复按钮或常驻抑制开关。

应用文案当前只写中文，未建立其他语言翻译表。发布包移除其他语言的独立 MUI 资源，只保留 zh-CN 和 WinUI 的 en-us 回退；共享框架 PRI 不重新裁剪。后续有真实需求再接入翻译机制，不提前维护多套文案。

20. 键盘检测/动作声明通用 `HotkeyList` 字段，主表单仅显示前三组合摘要及编辑按钮；应用内弹窗选择修饰键/按键并添加、移除，动作支持上移、重复组合，检测去重。批量输入折叠在弹窗内，最多 16 个组合，一次验证全部，错误保留输入，确认才提交、取消不改变原值。检测至少含 Ctrl 或 Alt、F12 系统保留；动作可单键，按序向执行时前台发送。目录提示解释占用/按住不重复、忙时不重放、延迟与暂停取消、输入已发送不代表目标功能成功，以及不能发送 Axiom 当前监听组合。没有键盘能力 ID 专用分支。

## 状态与文案

| 事实 | 用户文案/显示规则 |
|---|---|
| 配置已启用 | 已启用；不能写运行中或成功 |
| 配置已暂停 | 已暂停；配置仍保存 |
| 读取失败 | 后台状态未确认；缓存标为上次读取，不显示当前成功 |
| Agent 不可用 | 检测暂不可用；不能因宿主可连接就说正在监控 |
| HDR Enabled=true / Active=false | 已开启，但尚未生效 |
| 显示状态未知 | 状态未确认；不能当作已关闭 |
| 状态请求返回 | 展示绝对读取时间；不声称持续实时同步 |
| 回复丢失 | 结果未确认，保留输入，刷新核对；不宣称必定失败且自动重发 |

错误优先解释用户能做什么。内部异常/协议诊断留给技术记录，不能把长异常堆栈作为主要文案。已有后台原因尽量保留事实，后续协议结构化原因按实际需求增加，不让 UI 根据全局状态猜测某条规则执行成功。

## 视觉与可访问性

浅色为轻灰工作区、白色侧栏与内容卡、深色文字；深色为炭灰工作区、稍浅侧栏与内容卡、浅色文字；两者保留低饱和绿色主动作。一页只有一个主要任务。标题 30、卡标题 18–20、正文 14、辅助 12；统一 8/12/16/24 间距，避免大数字、编号导航、过多彩色徽章和装饰性空卡。

应用 EXE、任务栏和自定义标题区域使用同一几何 A 图标；标题栏融入当前主题背景，不再额外显示系统标题行。拖动区和原生最小化/最大化/关闭及缩放保持可用，按钮前景及悬停颜色随主题更新；弹窗使用工作台当前主题。系统模式使用 WinUI ActualThemeChanged 通知更新配色，无轮询；按钮在窄窗口内可收缩和换行。

列表整行占内容宽度，编辑表单单列且限宽；小窗口缩窄侧栏和留白、纵向滚动，不并排挤压列表与表单。原生按钮/输入/对话框支持键盘和可访问名称。不得仅靠颜色区分状态。实际窗口检查默认尺寸与窄窗，不能用 HTML 效果图代替 WinUI 验收。更广泛 DPI/高对比度矩阵属于发布检查。

## 实现职责与扩展

- WorkbenchWindow：导航、编辑会话、未保存保护、请求期间互斥与确认流程。
- 页面重绘先离开输入/可访问性回调，构造脱离可视树的内容和页脚，完成后一次替换 ContentControl.Content；不直接 Clear 当前页面子集合。此方式修复原生编辑回调返回期间的 UIElementCollection.Clear 崩溃，侧栏和外壳保持稳定。
- WorkbenchWindow.Keyboard：HotkeyList 的应用内组合键编辑、顺序、去重/重复和批量输入；只保存声明参数，不监听或发送系统按键。
- WorkbenchWindow.Theme / UiThemePreference：界面配色与外观偏好；不读写规则或请求后台动作。
- WorkbenchWindow.Activity：日期分组的活动列表、分页、刷新与七天清理；通过受权 IPC 读取，不访问数据库，不生成假历史。
- WorkbenchWindow.Catalog / Groups / Toolbox：统一类型/工具入口卡片；进程组管理与共享批量输入、Steam 开关和名单/排除设置弹窗；顺序展示弹窗，复用受权读写。自动同步由 Host 的 SteamToolManager 执行，不依赖 UI。
- WorkbenchWindow.Tray：TraySelection 的应用内当前托盘搜索/刷新/勾选；通过 Host 读取真实会话名单，草稿独立、取消不提交，按窗口高度限制列表，不订阅后台周期刷新。
- WorkbenchWindow.Views：目录选择和字段渲染器；支持文本、多行文本、布尔、枚举、资源、文件/目录选择与范围数字输入；字段 Group 生成“更多选项”折叠区域。类型切换只更新参数与依赖区域，不销毁正在操作的下拉框；没有程序能力 ID 的专用表单分支。
- TaskEditorState：版本化编辑配置；切换检测清除不兼容动作，切换能力清除旧参数，取消/刷新保护用户输入。
- WorkbenchClient：现有受权 IPC 请求、响应校验和有限超时；不决定规则、不调用 Provider 或 SQLite。
- WorkbenchPresentation：通用保存错误文案；具体动作的结果解释属于后台适配器。

能力扩展通过 [任务接入 contract](../development/task-authoring-contracts.md) 完成，不复制新场景专用页面。当前任务是一种检测配一种动作；组合条件、多步骤与可编辑执行策略尚未接入，不能只做按钮假装可用。策略当前展示已实现的行为，后续策略字段须同时接通引擎语义。

打开、切页、手动刷新和规则操作才请求快照，无刷新 timer。未来若需要及时结果，扩展有界事件订阅，仅在窗口需要时订阅、关闭即释放，禁止用秒级轮询掩盖数据流缺失。

## 使用观察页

工作台提供显式、限时的使用观察入口；正在记录的范围、暂停/继续/结束、到期时间和关闭窗口即结束的行为持续可见。记录本地分页，可删除，结束后可补充观察目的。建议卡先解释证据和限制，确认后进入未保存且暂停的规则草稿；不直接启用。摘要/能力目录/扩展任务在可编辑预览中由用户复制，AI 建议粘贴后交 Host 严格校验。观察后台连接结束会推送状态刷新，无周期轮询。
