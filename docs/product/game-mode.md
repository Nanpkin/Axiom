# 游戏模式（2026-10-22）

本轮由所有者明确授权先交付文档和配置UI，不改变任何子功能的监测实现。它是跨功能的资源策略，后续修改监测的agent必须遵守本页；不能把预设已保存写成已降低资源占用。

## 当前交付

设置页外观下方提供游戏模式配置预览：手动开启预设、按指定程序自动开启预设、程序名单与保存。复用检测能力的BuildProcessPicker：exe名称、多选文件、批量输入弹窗、从进程组勾选/全选，大小写不敏感去重、最多128项。选入后是独立名单，组变化不自动修改预设。

预设仅由UI保存到共用用户目录game-mode-preset.json，不是宿主运行配置；切页前需点击保存，未保存输入不保留。开启自动方式必须至少选择一个程序。保存失败保留输入；重开读取预设。界面始终明确显示尚未生效，不展示虚构的运行状态或节省比例。当前没有自动进程订阅，也没有改变任何监测频率。后续接入Host时须显式迁移预设并等待后台确认，不得把UI文件直接作为运行状态来源。

## 后续实现约定

- 手动开启与自动开启可以并存：有效状态 = 手动开启 OR（自动开启已启用 AND 任一所选程序运行）。关闭手动开关只释放手动请求；所有目标退出且没有手动请求时结束游戏模式。停止自动方式保留名单。目标已运行时启用自动方式也应立即读取当前状态。
- 自动检测复用现有共享进程通知/订阅及已知初始快照，不新增定时扫描。未知不能冒充全部退出；需展示未确认原因。关闭UI仍由后台管理状态。恢复和重启不重放一次性动作。
- 界面须区分配置已保存、模式已开启、哪些监测实际暂停/降频和未接入的项目。不得承诺所有监测都停止，也不得以模式开关代替规则的手动暂停。
- 每项监测逐个明确正常/游戏模式策略：继续、暂停、或降低已有采样频率。系统事件驱动来源无需为了降频改成轮询；降频仅用于已有必要采样，具体频率按对应能力成本与延迟决定，不在此统一指定。
- 暂停要停止实际订阅/采集工作；共享来源仍有其他消费者时按需保留。不能只隐藏结果或丢弃回调而宣称减少开销。自动进程检测本身必须保留，否则无法可靠退出模式。
- 涉及Desired State的暂停必须沿既有取消、恢复、Unknown和手动接管contract执行；恢复不明不能强制覆盖。退出模式重新获取状态，一次性动作不补发；规则原有手动暂停、HDR/时段门禁保持独立。
- 后续接入各子功能时更新其状态说明与精确验证；仅验证实际接入项目，不运行全套。未经测量不宣称CPU/GPU数值达标。

## 验收边界

本轮仅验收配置UI、进程选择复用与预设保存；后台状态、真实自动开启/结束、各项暂停/降频、恢复以及实际性能均留待后续明确实现。下一轮优先接通Host拥有的模式状态与共享进程订阅，再按具体成本逐项接入监测；本页不是自动启动这些工作的命令。
