# 当前状态与交接

更新：本轮云端迭代。当前是持续变化的小型 Windows 11 x64 自动化工具，HDR 只是第一个场景。源码以此可用版本重新开始 Git 历史；个人现场记录和原始验收证据只留本机，不作为云端必读资料。

## 入口与架构

- 本机预览：artifacts/Axiom-preview/Axiom.exe；分发包：artifacts/release。源码仓库不包含二进制，按 [分发说明](../development/distribution.md) 构建。
- 根目录 Native AOT 启动器；app 中的 Host/Session Agent/WinUI 共用自带运行库。Host 是 Service 角色，尚未注册 Windows Service。UI 完全退出后后台继续工作。
- 用户数据在 USERPROFILE 下的 .axiom，配置通过 Host/SQLite 写入。开发与正式入口访问同一数据根；不自动备份、不启用 EFS，不播种或恢复某位开发者的规则。
- 同账户 UAC 提权，登录为当前用户最高权限交互任务；安装版当前用户安装，有开始菜单、可选桌面入口及系统卸载登记。卸载保留数据，只清本安装所属登录任务。
- 按 [代码定位表](../development/code-map.md) 阅读本轮相关代码，边界见 [架构地图](../../ARCHITECTURE.md)。旧计划不是执行指令。

## 已实现

| 场景 | 当前行为和限制 |
|---|---|
| 自动化 | 声明驱动检测/动作/参数；保存、编辑、暂停、删除；名称/检测/动作搜索及启用状态筛选；各规则独立异步等待，同资源保留仲裁；不支持任意条件组合和完整多步骤流程 |
| 程序检测 | 原生 Win32_ProcessStartTrace 共享事件源和精确退出等待，无窗口依赖、无周期枚举；未知不当退出，初始已运行进程不补触发；极短进程可能错过身份核验 |
| 窗口状态检测 | `window.state-is`多完整exe路径，任一可见顶层无拥有者窗口最小化/最大化/普通即成立；隐藏或不存在不算普通，不读取标题。共享WinEvent，首次及Unknown恢复不补一次性动作，已知初始条件可保持唤醒；已过当前main Windows原生检查，真实状态待实机 |
| 启动检测 | 每次后台启动或本次开机首次；Windows BootId 持久化去重；打开 UI 不触发，新增首次规则不补执行，失败不自动重发 |
| HDR | 游戏开始按规则设置，结束按本轮基线恢复；手动修改、暂停或观察中断遵守接管边界；正在控制时拒绝停止后台 |
| 程序动作 | 启动支持参数、目录、延迟和实例策略；关闭支持正常/强制与多完整路径；隐式窗口隐藏不能强制阻止 GUI 自行显示 |
| 窗口动作 | 多完整路径、延迟、标题过滤、有界等待；关闭、最小化/最大化/普通还原、左右半屏/四角四分之一/中央80%、置顶/取消置顶；新接入执行时主屏/上一屏/下一屏移屏并居中80%。按需 WinEvent，一次处理后读回，不持续压制手动调整；移屏本批验证见下文 |
| 硬件屏幕亮度 | `display.hardware-brightness`默认主屏或明确全部支持屏幕，执行时公开Monitor Configuration API查询支持/范围，0–100映射后每块一次写读回；不绑定设备ID，不限定外接。未知不写，已知不支持跳过，部分失败计数明确；10秒单准入，真实硬件待验 |
| 当前媒体控制 | 一次向Windows选中的当前媒体会话请求暂停/播放/上一项/下一项，支持延迟及时段门禁；无指定应用或曲目信息。已暂停/已播放说明无需操作；成功仅为请求接受，切换/缺会话/不支持/权限失败有原因，不恢复或重试 |
| 当前媒体播放检测 | `media.playback-state`选择正在播放/暂停/停止或关闭，公开当前会话与播放状态通知，无轮询；会话切换/首次/Unknown恢复只建命令基线。无当前会话时三个条件均不成立；已知首次播放可保持唤醒，未知/结束/暂停释放。不能证明实际出声或所有应用状态 |
| Windows网络分类 | `network.category-state`公用/专用/域已验证单选，任一已连接网络已知匹配为true；无匹配且仍有查询未知为Unknown，明确无连接为false。公开分类及连接通知、共享MTA，无轮询/探测；不记录名称/SSID/ID，不把专用或域分类当安全身份 |
| Windows节能状态条件 | `power.saver-state`只按公开兼容电池节能API的0/1选择已开启/已关闭，其他值Unknown；不按电池/电量/方案推断、不表示新版节能强度。共享通知后只读；首次/恢复baseline，排除方案/保持唤醒反馈，实机待验 |
| 电源方案条件 | `power.scheme-state`按标准GUID选择平衡/节能/高性能；有效自定义方案已知不匹配，不混同电源模式滑块，不改方案。共享通知后只读，首次/恢复baseline；方案切换动作排除自反馈，实机待验 |
| 会话屏幕电源检测 | Windows当前交互会话亮/暗/关通知，无轮询或逐屏选择；首次、重新启用及Unknown恢复建基线，不补动作。可组合音频/媒体/提醒/关闭程序；不组合保持唤醒或显示设置 |
| 托盘动作 | 当前可识别图标面板，多选、搜索、刷新；完整路径和 SID/会话核对后一次删除 ID/GUID 图标；未公开系统记录格式有版本限制，重建后可能再出现 |
| 组和工具箱 | 进程组批量输入、文件多选、组内勾选；Steam 工具按启动扫描元数据，缓存按通知失效，维护固定组/排除项，不递归扫描游戏目录；已保存规则不会自动跟随组 |
| 快捷键 | 设置中切换 Axiom 窗口；规则检测多组合、动作有序发送可重复组合及延迟；共用唯一 RegisterHotKey 消息线程，无轮询或键盘 hook；按键只发前台，拒绝自身监听组合循环 |
| 活动与主题 | 持久活动日志、按可视高度分页、清除七天前日志；主题默认跟随系统，可浅/深色切换；批量输入用应用内弹窗 |
| 扩展 | 内置 IAutomationPlugin / ISessionCapabilityProvider 注册扩展，通用 Engine/存储/IPC；无外部 DLL 热加载或市场，HDR 恢复适配器独立 |

任务栏自动隐藏新动作`taskbar.auto-hide`：从“按快捷键开启任务栏自动隐藏”暂停模板填写快捷键，选择开启或关闭（始终显示）、延迟及可选时段，保存审阅后启用；也可配程序/前台/窗口存在与合理系统/定时事件。一次读当前Windows系统任务栏设置，只修改自动隐藏位并读回；已一致不写。设置保留，暂停/删除不恢复，UI退出规则继续；鼠标边缘、通知或系统仍可展开。只核验当前用户活动会话的原Explorer/Shell窗口，不逐屏、不完全隐藏、不持续强制、不杀Explorer或写注册表。5秒单准入、取消/超时可能已写，失读/身份变化不写或报告未确认，不转而操作新Shell、不重试。4项合成测试与Agent构建通过；云端未调用真实Windows任务栏API，Windows11实际设置/多屏/Explorer重启效果待实机。

## 关键语义

- 文件到达检测按用户填写的目录监听新建/重命名，仅扩展名筛选、非递归、无初始扫描；首个事件起一秒合并为一次。最多16种目录/类别组合，同目录共享通知；不读取内容、不证明下载完成、不传文件名给动作，也不纳入主动观察。UNC/映射网络驱动器不支持；移动目录后需更新路径并重启检测。文件通知故障只令文件检测未知，其他能力继续。
- 相关性不是因果，不能声称节省时间。缺口、重新显示或Axiom动作等中断相关序列；已知Axiom动作目标排除。接受只进入编辑器，正常关闭候选不强杀、不自动重开。
- 完整路径/本机对象映射留本地；匿名别名为每次观察的随机值。导出和任务包均不自动上传；导入不执行代码、URL或自由形式指令，仍须通过参数/能力/组合/对象检查。必须手工选择的目录/网址/显示器允许空占位，确认页列出待填项；正常保存/编译仍严格要求补齐，非空自由路径/设备值不接受。

## 本批电源方案上下文

用户可在通用编辑器选择“当前Windows电源方案”并组合亮度、音量、提醒、打开工具或保持唤醒，保存后独立暂停/启用；“使用标准节能方案后调暗内置屏幕”模板默认暂停。首次已成立可建立Desired请求，一次性动作只响应新边沿；结束、Unknown、暂停或停止收回Desired。UI退出仍由Session Agent检测。

公开GUID_ACTIVE_POWERSCHEME通知为提示，64有界合并后一次PowerGetActiveScheme并LocalFree，无轮询或电源写入。有效自定义GUID是已知false；空GUID、读取失败、畸形通知/挂起为Unknown，恢复仅建基线。新注册失败仅拒新消费者，新消息不形成旧供电/电量动作边沿；队列溢出只使对应租约未知。4项合成状态/Provider/Engine/保存与严格导入检查，以及Agent/Provider交叉构建通过。新增Windows原生只读查询/自有窗口过滤与旧共享过滤复跑交由Windows CI；实际方案/策略/挂起恢复待设备验证，不称实机通过。


本批同时接通“Windows报告的电池节能状态”`power.saver-state`，以及默认暂停的开启后调暗内置屏幕模板。公开GUID_POWER_SAVING_STATUS只作提示，读取GetSystemPowerStatus.SystemStatusFlag，仅文档0/1已知；不要求电脑有电池，不假定新版节能功能/强度支持，不以电量阈值/电源方案/模式替代。未知不当关闭，注册失败仅拒新条件，新消息不触发旧电源边沿；不组合方案切换或保持唤醒，不修改节能状态。两条件共用局部PowerContextObservation合并/失效/基线helper，各自状态解析和Provider独立。每能力4项合成检查通过，提取helper后方案4项直接复跑通过；Agent/Provider交叉构建通过。新增Windows原生用例仅自有窗口通知与只读SystemStatusFlag，Windows CI及真实设备/策略待验。


## 亮度相对调整增量

新增`display.brightness-adjust`与`display.hardware-brightness-adjust`，在已有内屏WMI/支持硬件屏模块中选择提高或降低1–100整数百分点；内屏沿用全部支持内屏，硬件沿用主屏/全部支持屏幕，旧绝对设置schema与默认行为不变。每块目标先读已知当前值再一次写读回，到原范围端点限幅；硬件用UInt64将幅度四舍五入到原生单位，粗粒度可能保持原值。未知不写，部分结果明确，不自动恢复或重复累加。

两个默认暂停快捷键模板分别降低内屏5个百分点、提高主屏硬件亮度5个百分点；可编辑方向/幅度/延迟并保存、严格导入和暂停，界面退出后台继续。相对与绝对共享原native Commands准入，取消/超时保持原生资源到真实返回。2项新增合成检查及2个直接受影响的旧注册检查通过；Agent/Provider构建零警告/错误。未运行真实亮度读写或全套/目录预算；实际WMI/DDC/CI/粒度与驱动待设备验证。
