# 功能目标与持续开发清单

## 所有者的持续要求与当前主线

2026-10-09 所有者再次明确：四阶段最小闭环已接通，当前回到**大量提出并开发真正有用的检测能力与动作能力**。先忽略已完成的阶段任务，主动发现 Windows 日常重复操作的痛点并交付新能力；建议排序、观察细节和界面零碎完善不继续占据开发主线。提醒、观察、建议与源码扩展只做新能力确实需要的接入或已有缺陷修复。

持续推进，不因一个阶段、测试、提交或 PR 结束而停下。所有目标、头脑风暴、实施顺序、API 障碍与交接必须留在仓库，不能只留在聊天中。已授权范围内自主实现与验证，每个有意义且完成相关验证的增量及时 commit/push；有实质阻塞则记录证据并继续其他独立能力。模块数、测试数、文档数量不能代替用户新增能完成的事情。

四阶段产品路径仍有效：实用 Windows 自动化 → 用户主动开启的限时、低敏感本地观察 → 有证据的可审阅建议及无需 API Key 的离线 AI 辅助 → 用户确认的源码功能扩展任务。它们已是可复用路径，不能继续被当成待建地基。确定性引擎执行规则，AI 不参与运行时；关闭 UI 后规则继续、主动观察结束。未知不能当作否定，Axiom 自身动作不能冒充用户习惯。维持私有草稿 PR 与准确提交对应的便携版、安装版，不擅自合并、发布 Release 或替换所有者现场。

## 已能使用与不重复开发的范围

已有程序/窗口/前台/系统/默认音频/文件到达/快捷键/多种定时检测；程序、窗口布局、托盘、键盘、目录/网页/本机文档、默认播放音量/默认通信麦克风和桌面提醒动作，以及原有18个场景模板；本批新增时间门禁、保持唤醒、应用音量和Wi-Fi检测及3个模板（整体验证见当前状态）。主动观察、证据建议、反馈、匿名摘要、严格导入、暂停草稿与源码扩展任务已接通。准确行为、验证和限制以[当前状态](current-state.md)为准；CI 不能代替所有者实机验收。

已核对实际注册及声明：`BuiltInAutomationPlugins`、`SystemEventCapabilities`、`AudioPlaybackCapabilities` 和 `WindowsSessionEvents`。现有 USB 是任意接口类别接入/移除，显示检测是模式变化，网络检测是本机接口可用性，音频检测是默认角色变化；**均不等于精确设备或指定网络选择**。原播放动作只改默认设备主音量；本批新增指定应用音量独立动作。新候选不重做这些已有类别能力。

## 保留的后续想法与已知 API 障碍

- 有限有序动作仍有价值：一次打开计划文档、启动工具、整理窗口；之后围绕具体场景做最小逐项结果、失败策略和取消。当前不把工作流大框架或任意 AND 条件当作交付前置。
- 完整工作布局恢复仍是后续候选：用户显式保存窗口布局，处理缺屏、混合 DPI、多个同应用窗口及手动调整。先交付上表的指定屏幕动作，不把完整恢复系统当成必须先做的基础设施。
- 默认播放/录音设备切换：检测默认设备变化已有公开通知，切换系统默认设备缺少相应稳定公开 Core Audio 设置接口；未经专项 API 与权限核实，不依赖未公开 `PolicyConfig` 冒充可靠通用能力。
- 文件自动归档：已有文件名新建/重命名通知不证明写入/下载完成。若做复制/移动，要先选具体受支持流程，说明重名、占用、取消和数据保留；不存在通用“文件已下载完成”事件，不能默默轮询所有目录。
- 用户空闲/持续无操作：通用 `GetLastInputInfo` 只提供查询，并无可靠的任意空闲阈值系统通知。没有合规低成本设计及取舍证据时不提升为下一项，更不能开启键盘 hook 或采集输入正文。

每轮先写用户新增能完成什么，再核对相关实现、API/权限、事件源与验收。只处理会挡住本项功能、构建、隐私边界或真实正确性的配套问题；新能力的编辑、保存、注册与必要观察/建议接入跟随该能力。需要恢复的持续状态才设计本能力的接管与释放；一次性动作须明确不自动回写旧值。
