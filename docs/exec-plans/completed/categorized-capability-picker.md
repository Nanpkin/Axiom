## 范围与实现

- 复用能力目录的类别、名称、说明与兼容声明，共用一个应用内 ContentDialog，不按能力 ID 写专用分类。
- 覆盖常规检测类型、动作类型、组合叶状态类型。单个/组合模式和各参数的小选项控件保留。
- 主表单展示紧凑当前选择与打开按钮；弹窗提供类别入口、名称/说明搜索、单选列表和确认/取消。
- 取消只丢弃弹窗草稿；同一类型确认保留原参数；不可用原配置不丢失。确认仍走现有编辑状态接口及组合树代际守卫。
- 负责人协调、审查、实机验收与 Git 操作；子任务 agent 实现源码及必要合成检查。不修改已有规则或执行真实动作验收此 UI。
- 云端核心检查暴露既有 gap 恢复与配置变化的竞争：不得放宽超时或跳过；限定为直接根因与确定性回归的修复，保持 Unknown 后须显式恢复或新配置/模式的原契约。

## 验收路径

1. 新建任务分别打开检测/动作弹窗，按类别选择，搜索及空结果检查，取消保持原值，确认显示相应参数。
2. 同一类型已填参数后重开并确认，原值保留；切换检测后的动作候选仍遵守既有允许对。
3. 组合持续状态的子条件复用分类窗口，过滤一次事件和不兼容类型；取消/确认及树结构变化保护有效。
4. 深浅主题、800×650 窗口、长列表滚动、键盘和关闭弹窗可用；未保存退出提示仍有效。
5. 相关合成检查与 WinUI Release 构建通过。按既有授权安全停止当前应用，统一脚本更新固定本机预览并重新启动，核对版本/来源、后台连接及用户规则保持。
6. 匿名结论更新当前状态、UI 规范及定位表，及时 commit/push；CI/发布遵守现有功能批次流程。
