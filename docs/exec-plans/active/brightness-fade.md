# 可选亮度渐变与推荐规则

2026-10-18。一个实现代理负责相关代码，负责人审查、文档、验收与Git。

用户可在全部六个亮度动作中选择渐变与过渡用时，并在本机得到几套画面降亮方案，一套温和方案启用。验收只覆盖新字段、有限渐变及恢复/让出、相关UI和本机配置读回。

- 沿用现有亮度目标选择、原生准入与恢复租约；旧参数省略渐变保持原行为。只在过渡期间有限调度，不增加常驻轮询或多次重新选屏。
- 取消停止后续写入；未确认写入不重试；手动改动、拓扑或未知仍让出。正常恢复也使用渐变且保留最初基线。
- 只运行本轮与直接受影响边界的测试，清单不沿用托盘测试；复用此前画面采集/HDR验证，不做全量回归。
- 本机先读取既有亮度规则，避免推荐方案争用；用户已明确授权保存备选并启用一套温和方案。不上传配置、日志或设备信息。
- 相关验证后commit/push，统一安全更新固定预览并核对来源、连接、原配置；再经应用接口保存/启用推荐方案并读回。受控游戏/停止拒绝保留现场。

实现：六动作共享渐变开关和1–15秒过渡，默认关闭/3秒；原生批次250ms最小步距、同值去重、保持原目标和基线。预算已贯通原生/Provider/Host；正常停止单独增加期限，其他请求不变。

相关验证：63项不同纯测试有效通过（原56+4直接边界；修正11项复查含新零距离1项、协议2项），Agent叶构建通过；一次审查发现零距离仍等待与正常停止期限不足，仅局部修复/精确复查。实机/UI与正式推荐配置待本机更新后验收，测试不扩大。
