# 游戏模式状态检测

目标：设置中的手动/自动游戏模式由后台持久管理，UI退出仍工作；用户可在通用检测中通过AND/OR/NOT决定规则行为。现有任务不自动改变，两条定时亮度明确不受游戏模式影响。

最小范围：复用声明/组合编辑与Engine，新增Host游戏模式设置和本地状态源、复用Agent进程观察；设置页连接真实回执。新增文件仅用于该设置/声明/状态生命周期，避免扩大成策略框架。

- [ ] 后台：声明/严格协议、原地存储、手动OR自动状态、Unknown/基线/退出生命周期。
- [ ] UI：紧凑设置二级页真实状态/保存、原进程组选择、错误/草稿保护；旧UI预设显式导入。
- [ ] 集成：组合与一次命令基线、设置重启、目录预算与直接相关测试。
- [ ] 文档：纠正定时亮度建议，解释组合不代表停止其他检测；更新交接/Git。
- [ ] 必要本机验收及安全替换（拒停/恢复不明保留现场）。

分工：backend agent持有Contracts/Infrastructure/ServiceHost及相关测试；UI agent持有WinUI；负责人文档、集成审查/验证/Git/本机验收。代理不提交，负责人合并本工作区的必要增量。

验证只选本轮相关类/精确方法，不跑全套。逻辑组合不扩展为采集短路；不得宣称新增了全局自动暂停或降频。
