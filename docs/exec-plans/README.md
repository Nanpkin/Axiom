## 历史如何保留

| 目录 | 含义 |
|---|---|
| [completed](completed/README.md) | 当时范围内完成的计划与验收证据；不是当前路线，不代表完整产品或全部专项已验收 |
| [archived](archived/README.md) | 停止沿用的 0004、0008；开发预览已交付，未全项验收，不能移入 completed 假报完成 |
| [active](active/README.md) | 当前为私有仓库与云端准备，长期迭代目标待确认 |

历史正文不追写新进展；其中旧“状态”“下一步”“必须先做”、旧预设和备份步骤只描述当时阶段。仍有效的行为边界以当前 contract/ADR 为准；当前缺口已汇总到交接页，未验证事项没有被撤销或改记为通过。

## 新任务何时建计划

复杂任务先写本轮主计划：用户能完成什么、操作验收路径、范围、相关规范、实施步骤、验证与剩余事项。小修复和文档维护可直接执行，不为延续编号拆出大量计划或复审计划。

计划只服务本轮明确需求，不自动启动候选功能、不追赶历史待办。已有授权内推进，实际 diff 和直接风险验证通过即交付；额外审查须有新问题或具体消费者。CPU 策略持续遵守，数值测量按 [性能政策](../development/performance.md) 安排。

完成且有证据的计划归入 completed；未完成但不再沿用的计划归入 archived，说明终止范围并把仍相关缺口放入当前状态。不得把构建成功当 UI 验收、把 fake 当硬件证据、把核心短基线当全后台性能。
