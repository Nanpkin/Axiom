# 游戏模式 Wiki

游戏模式为自动化规则提供“正在游戏”的状态。你决定哪些规则使用这个状态；开启游戏模式不会统一暂停所有任务。

## 如何开启和结束

- 手动开启：保存后保持开启。关闭手动开关后，仍会按自动检测决定是否开启。
- 自动开启：开启自动检测并选择程序，任意一个运行时开启；全部退出且没有手动开启时结束。程序可以从进程组勾选，也支持批量输入和多选程序文件。
- 手动与自动可以同时使用。自动检测不确定时显示未知，不会直接当成已经结束；手动开启仍能确定游戏模式已开启。
- 关闭 Axiom 窗口后后台继续工作。设置页显示读取时的状态，点击刷新查看最新结果。

## 已经改变了哪些逻辑

- 新增游戏模式状态检测，供规则判断“开启”或“关闭”。手动与自动使用同一份后台状态，配置保存后重启仍保留，自动进程状态会重新确认。
- 可以使用“全部满足”（逻辑与）、“任一满足”（逻辑或）和“不满足此条件”（逻辑非），自行决定游戏期间的规则行为。
- 首次读取、重新连接或新建规则不会补发一次性动作。持续动作按已知条件及该动作原有的恢复规则处理。
- 旧版只保存界面预设的配置不会自动启用。可以在游戏模式设置中导入原预设，核对后再保存。

## 示例：游戏时不自动降低亮度

新建或编辑规则，选择“多个条件”，使用“全部满足”，加入画面明亮条件，再加入“不满足此条件：游戏模式状态为开启”，最后选择需要的亮度动作并保存。

这样，只有画面条件满足且游戏模式关闭时，整条规则才成立。游戏模式状态未知时，“不是开启”也仍然未知，不会冒充已经关闭。

如果希望某条规则只在游戏期间生效，则使用“全部满足：原状态条件、游戏模式状态为开启”。每个条件仍须支持同一个动作，界面不会开放未接通的组合。

## 哪些行为保持原样

- 现有规则不会自动加入游戏模式条件。未添加游戏模式条件的定时亮度规则继续原有调度，不受游戏模式影响。
- 游戏 HDR、音量、麦克风、窗口、网络与工具箱均不会因为游戏模式开启而自动改变；需要由你明确配置相应规则或工具。
- 手动暂停的任务不会因游戏模式结束而重新启用。原有 HDR、时段限制和手动接管继续生效。

## 当前还没有做的事

“条件不成立”和“停止采集”是两回事。普通逻辑与、逻辑非可以阻止动作，但不会自动停止其他条件的监测。例如画面检测与“非游戏模式”组合后，游戏期间不执行自动调光，画面采集仍可能继续。

目前没有针对各监测统一实施游戏期间暂停、降频，也没有已验证的资源节省比例。以后若接入具体项目，本页会列明实际变化，不能把候选策略当作已生效功能。

## 亮度和其他设置会自动恢复吗

已经完成的一次性调光不会因为开启游戏模式自动变亮。只有明确标注“条件结束恢复”的动作，才沿该动作的保护规则尝试恢复最初设置：目标和当前值必须能确认，外部改变或状态未知时不会强行覆盖。

条件结束可以取消尚未发出的请求；已经发出的启动、关窗、按键等动作可能已经生效，不能自动撤销。结束游戏模式不会补放游戏期间错过的一次性动作。

## 保存与阅读说明

修改设置后需要保存，后台确认才算已保存。失败或版本冲突保留输入；“重读已保存配置”会先确认是否放弃未保存输入。返回、切页和刷新保留本窗口草稿，关闭窗口会提示确认。

本页说明随应用版本一起提供，只描述该版本已实现的行为；后续游戏模式变化会同步更新这里。
