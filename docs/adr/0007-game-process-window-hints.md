# 0007 — 当前用户会话的游戏进程通知

状态：Accepted（开发预览）。日期：2026-09-27。

## 背景

首个自动化需要在普通用户会话中识别指定游戏进程启动/退出，CPU 空闲时不能固定扫描。当前机器普通用户订阅 `Win32_ProcessStartTrace`/`StopTrace` 返回 Access denied；WMI `__InstanceCreationEvent WITHIN` 属定期查询，不作为零轮询通知源。正式 Windows Service 身份下的其他通知能力尚未验证。

## 决策

Session Agent 仅在存在启用的游戏规则时订阅 `SetWinEventHook` 的顶层窗口创建/显示提示。提示只提供候选 PID；随后核对规则中的 `.exe` 名、可读取的完整镜像路径、当前用户 SID、会话 ID 与进程启动时间，并以进程句柄异步等待精确退出。用户可选完整路径限制，但默认按进程名，不绑定安装位置。订阅先建立，再做一次启动快照；通知队列有界，缺口时重新快照。无有效规则时注销窗口钩子，停止观察。

窗口提示可能晚于游戏初始化，且无窗口的进程不会被发现。因此当前实现不保证 HDR 在游戏最初读取设置前完成；实际原神、CS2 的通知时点和游戏内生效仍需验证。后台启动时已经存在的游戏只做基线识别，不推断其启动前 HDR，也不自动接管。

## 重连等待与 CPU 成本

Agent 到宿主的长期管道连接关闭时立即感知断线。宿主尚未运行时，Agent 每 5 秒尝试一次本机管道连接，连接成功即停止重试；它不枚举进程、不读取显示器、不激活观察钩子。普通用户会话没有可直接等待“特定宿主管道创建”的现成通知，因此暂用只在宿主不可用期间的有界间隔重连。宿主连接期间没有健康轮询。预计空闲成本仅为断线期间每 5 秒一次失败的本机连接；当前混合负载机器不用于数值验收，按 [性能政策](../development/performance.md) 在专项诊断或发布前测量。

## 后果与替代

不会为了早期通知而要求普通用户管理员权限；也不对所有进程固定枚举。若目标游戏创建窗口前已经锁定 HDR，需要改用经权限验证的更早系统通知或明确的启动器工作流，并单独更新计划；不能把当前窗口提示宣称为进程创建事件。进程挂起不在本决策内。
