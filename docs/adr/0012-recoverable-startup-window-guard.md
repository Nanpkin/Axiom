# ADR 0012：显式、有限期且可解除的启动窗口遮蔽

2026-10-28，接受为实验选项。所有者要求Axiom启动HECATE时避免窗口闪现，同时保留原入口再次打开窗口。普通SW_HIDE已正确使用但不能阻止后续显示；跨进程DWMWA_CLOAK在本机被拒；独立Desktop改变托盘与重新打开行为。故为当前需求增加一个原生组件，旧隐藏模式保持不变。

## 决策

- 只扩展program.start的显式`startup-hidden`窗口选项，用户选择后才加载组件。Domain/Engine无Win32或注入依赖，UI仍使用声明字段，Agent通过原程序命令链执行。
- 仅x64桌面程序；不用于游戏/受保护程序。不增加外部任意DLL路径、脚本、跨账户或全局桌面钩子。新进程由Axiom按已校验完整路径直接创建，挂起主线程，初始化加载器并核对系统入口，再加载同一构建的保护组件，确认准备完成后恢复主线程。失败只可结束本次尚未恢复主线程的新进程；恢复后失败、取消不强制结束程序。
- 在目标进程内、窗口创建和显示前设置DWM cloak。应用目录及其子目录延迟加载的窗口插件也处理；只处理窗口类所属模块位于应用目录的顶层窗口，系统输入法等辅助窗口、message-only及子窗口不作为遮蔽目标。不声称覆盖动态解析创建API、其他进程、任意DII初始化窗口或所有GUI框架。
- 默认最长15秒，用户可选1–20整数秒，给既有40秒程序命令截止保留初始化/恢复时间。首个已遮蔽可见窗口自行隐藏/关闭时提前结束；一个进程内等待句柄和最近截止，不轮询。
- 结束先停止新干预、恢复创建/隐藏相关IAT，再确认窗口隐藏、解除cloak。仅在被本次强制隐藏的窗口上保存恢复标记；保留SetForegroundWindow/SetActiveWindow/BringWindowToTop三项激活入口的进程内IAT包装，应用在完成清理后再次请求激活该窗口时先显示并消费标记。已可见窗口只移除标记，未标记窗口原样透传；这些包装不再隐藏、无等待线程或轮询，不依赖Axiom继续运行。窗口销毁时系统清除标记，避免原句柄复用误命中。延迟消息只移除窗口附加状态，绝不再次隐藏窗口，避免把后来的手动打开覆盖掉。恢复未知报告失败，不能仅因启动请求已发出而报告保护完成。
- 保护期间暂借已有共享原生进程订阅，按SID/会话/完整路径核对再次启动的实例，尝试提前让出并保留其打开意图；结束即释放。极短命启动器可能已退出而无法核对，明确不承诺任意保护期内的点击都可识别。保护结束后不继续拦截手动显示或新窗口。
- 启动遮蔽的目标按非管理员桌面权限运行，不继承Agent的管理员权限。通过GetShellWindow取得同会话桌面进程，核对其TokenUser与当前账户一致，使用公开父进程属性继承桌面令牌；环境按同一用户生成，进程/线程对象明确授予该用户及SYSTEM权限、采用中等完整性。创建后再核对目标未提权；桌面本身提权、身份不符或必须管理员运行的程序明确拒绝，不回退为管理员目标。Host/Agent/UI角色的管理员要求不变。
- 保护组件所需的共享内存与事件是未命名对象，句柄只复制给本次已创建的目标进程。避免跨完整性打开命名对象，不放宽UIPI消息过滤，不增加跨账户通道。
- 取消触发同一隐藏→解除流程，程序保留；目标挂起或恢复失败不能宣称可打开。截止后应用新弹出的窗口不再受本次保护，不能将此功能宣传为全生命周期禁止GUI。

## 文件与更新

组件以MSVC x64静态CRT构建、随统一包分发。宿主只从程序集目录加载其固定组件；目标加载经SHA256核对的同字节临时缓存副本。副本按内容哈希复用，目标保留DLL引用也不锁住固定预览目录。只尝试清理至多32个旧哈希DLL；仍被目标加载的文件保留，后续按需再清理。不复制用户配置、不建配置备份或每轮预览版本目录。

保护结束后DLL可能仍被目标加载，以避免并发回调/替换窗口过程中的不安全卸载；其创建/加载/显示IAT已恢复、保护标志关闭、等待线程退出；三项仅用于恢复显示的激活包装可能保留到目标退出。这个加载引用不代表持续隐藏。不承诺零资源占用，未测CPU数值不称性能达标。

## 验证边界

本机合成窗口验证首次显示前遮蔽、自然隐藏/截止解除、手动打开和新建窗口；HECATE使用其`-startup`参数时，启动临时窗口的显示事件已cloaked，解除后原入口可显示未cloaked主窗口。实际Axiom调用路径及取消另作针对性检查。原始记录仅本机，见[研究记录](../development/window-previsibility-research.md)。未逐帧捕获、未验证耳机硬件效果、x86、多账户、所有Qt版本或广泛应用兼容性。

前轮“原入口重开”由管理员夹具执行，不能代替桌面普通点击。用户反馈后复现：目标无cloak但已提权，普通打开无窗口，同权限打开成功。修正后必须由独立非管理员调用方验证打开、关闭窗口、再次打开，并核对目标非管理员及两次显示均无cloak。

后续开机反馈纠正：先前全部HECATE验收传入其自身-startup参数，不能证明空参数配置可恢复。空参数下截止时直接原生隐藏会使Qt保留逻辑可见状态，普通重开仅请求激活而不重新ShowWindow。新恢复包装必须覆盖这条路径；IME由系统模块注册，即使创建发生于应用调用栈也不遮蔽，避免解除时E_INVALIDARG。验证用实际空参数、非管理员调用、同PID连续打开/关闭/再打开，并通过保存任务的真实Agent链复核；本机重启不以夹具替代。

## DSX与日志修正

多个目标各自保护，不通过全局锁排队等待整个保护期限。原生导入处理仅接受PE64原生映像，排除PE32及带CLR目录的托管程序集；它们的导入由运行时管理，不作为原生GUI导入处理。DSX复现时主线程与清理线程阻塞于保护组件导入处理锁，排除托管程序集后启动器能正常完成本进程保护并拉起主程序；不增加超时掩盖阻塞。

保护只覆盖Axiom直接创建的进程，启动器/Steam另行拉起的主程序不在范围，选项必须明示。没有确认遮蔽到窗口时回执明确说明，不把启动器创建当作整个应用GUI保护完成。保护期内同一进程新窗口仍会遮蔽，极短命再次启动仍可能无法核对，不承诺保护期内所有手动操作都可识别。

命令活动复用已有Subject存冻结命令来源对应的任务名，不增数据库字段或UI页面。原生报告补阶段、主线程已恢复与进程存活状态；失败回执给出程序名/PID、阶段、错误码与状态，不把进程存活等同应用就绪，也不泛称所有失败目标都已在运行。
