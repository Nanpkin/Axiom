# ADR 0004 — 事件驱动与 CPU-first

- 状态：Accepted（用户已确定的方向；本次文档固化）
- 日期：2026-09-26
- 来源：本次明确需求；补充实现默认值见 决策状态（本机历史记录）。

## 背景

用户长期后台运行且玩大型游戏，平均内存低不能弥补持续唤醒和 CPU 抢占。

## 决策

CPU 与唤醒优先；禁止无理由轮询。优先适用的 ETW/WTS/Power Notification/Windows 通知，依赖索引选规则、Provider 按需激活、日志批量、失败指数退避、只等待下一 deadline、UI 可退出、Web/Remote 默认不启动。

## 替代方案与取舍

拒绝每秒扫进程/全规则、无界队列、为统计维持永久 timer。必要轮询须有 API 证据、预算与停止条件并新增 ADR 例外。

## 后果

事件源有丢失/风暴成本，需要有界队列、gap 和恢复。不得为省电破坏正确性；低内存不通过主动频繁 GC 换取。

## 验证

ETW/WPR/WPA 或 PerfView 加微基准，测全进程 CPU、唤醒与游戏影响。数值仅以 [performance](../development/performance.md) 为权威，当前均未实测。

2026-09-27 验证时点细化：上方是产品性能验证方向，不要求每次开发运行上述工具。用户明确开发期优先检测方式和工作策略，混合负载环境不作严谨数值验收；日常策略检查、异常诊断和发布前测量依 [performance](../development/performance.md) 执行。CPU-first 与必要轮询例外的证据/预算/停止条件要求不变。

## 变更规则

改变本决策须新增 ADR 说明原因、影响与迁移，并标记 supersedes；不得静默改写本条历史。实现参数的细化不自动构成架构推翻，但必须同步相关规范与证据。
