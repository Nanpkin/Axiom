## 测试方式与工具限制

内容控件使用 .NET `System.Windows.Automation`：以窗口所属进程与完整可执行路径限定范围，原生 `PropertyCondition` / `AndCondition` 定位，使用 `InvokePattern`、`ValuePattern`、`SelectionItemPattern` 和 `ExpandCollapsePattern` 操作。在同一提权助手内批量执行，等待目标控件出现，关键节点才读取控件树或截图；不逐步启动进程或全屏图像识别。提权通过正常 Windows 流程，仅为访问同账户管理员 UI。

本轮实测一个八步弹窗/取消/模板批次为 824 ms，七步导入纠错批次为 212 ms，仅是测试助手操作耗时，不是应用性能验收。页面后台读取会异步重建控件，定位需要有界就绪等待；过早定位失败不能算产品缺陷。

本机顶层窗口的 `TransformPattern.Resize` 曾使窗口隐藏但进程仍在，标题栏 Close 的自动化调用也未可靠发出关闭请求。因此窗口尺寸和关闭改用同一已核验窗口的标准 `SetWindowPos` / `WM_CLOSE`，普通控件仍走 UI Automation。标准方式复测正常，不能据这两次测试接口行为认定普通拖动或关闭存在产品缺陷。

原始控件树、测试助手、截图和本机核验结果仅保留在 Git 忽略的 `artifacts/ui-preview-smoke`，其中可能包含本机界面内容，不上传。此页是匿名结论，新环境不依赖原始现场资料。
