# 游戏 HDR 开发预览 contract

本页定义当前 HDR 适配器行为，不替代最终 Windows Service、多会话和硬件验收；产品进度只看 [当前状态](../product/current-state.md)。0008（本机历史记录） 已停止沿用，仅供查询历史证据。

## 用户行为

- 规则包含名称、1–128 个 `.exe` 进程名、活动显示器、HDR 目标开/关、暂停状态和版本。进程选择器支持组勾选、全选和手动添加，底层仍保存每行一个的独立名单；任意一个运行即满足检测，全部确认退出才结束。启用的 HDR 任务合计 128 个不同目标限制不变。按进程名匹配安装位置可变的游戏；观察器仍从 OS 核对实际进程 SID、会话、路径可读性、PID 与启动时间。相同名字的另一个同用户进程仍可能匹配；当前 UI 不提供可选路径限定。
- 规则经宿主写入 `%USERPROFILE%\.axiom\preview-rule-drafts\game-hdr.db`，避免打包父进程的 AppData 重定向。版本不匹配拒绝覆盖；最多 32 条，已启用任务合计最多检测 128 个不同进程名。旧单进程数据库在 schema 1 → 2 原库事务迁移，旧行保持原值并映射为一个进程的列表；按 2026-10-01 用户要求不再自动生成备份。删除和暂停后重新计算观察需求；HDR 与程序能力共用原生通知，最后一个消费者停止时注销。
- 第一次在后台运行期间观察到游戏新启动时，读取目标显示器 HDR 状态作为本轮恢复值。后台启动前已运行的游戏只加入初始快照，不当作新启动；该次不自动切换。多个已运行游戏对同一显示器要求相反状态时，Engine 冲突仲裁停止新切换。
- 退出时在没有仍需控制该显示器的游戏后恢复记录值；多进程任务中关闭一个仍有其他程序运行时不恢复。若有进程状态 Unknown，不能把它当作全部退出。若在下一个相关进程事件时发现 HDR 已被外部改动，则取手动接管并放弃本轮恢复；再次保存启用规则可释放该接管。游戏正在运行时暂停、删除或修改规则会让出本轮 HDR 控制，保留当前物理状态，不再对本轮退出自动恢复；下次新启动重新记录基线。Agent 断线会让出本轮控制并将输入置 Unknown，重连后重新快照；通知缺口也先禁用执行并重新获取快照。
- HDR 设置是单一绝对布尔目标。Agent 在写前再次读状态，要求它仍等于宿主记录的本轮预期值；若期间被外部改动则拒绝写入。执行后重新读取 `UserEnabled` 与 `Active`，二者均达到目标才算确认。断开显示器、不支持 HDR、启用但未生效或状态读取失败都不进入可写的 Known 状态。此检查不能消除 Windows 读取与写入之间的极短竞态。2026-09-28 原神新进程触发 M27T6S 实际 HDR 开启，两项读回值均为 true；正常退出后自动恢复关闭，两项读回值均为 false。用户反馈 CS2 已实测正常；具体回读/恢复证据尚未记录，游戏内效果仍待验证。

## 进程和 IPC

- 宿主拥有 Engine、SQLite 和规则判断；管理员 Session Agent 持有当前会话原生进程观察与 HDR API；WinUI 只调用宿主。管道仅允许本机，所有者明确为用户 SID、ACL 限该 SID 与 SYSTEM，客户端发送前核对实际 User SID，服务端再核对 OS SID、客户端 PID/会话；Agent 控制还须来自宿主，进程事件须来自 Agent。正式服务身份、签名、跨会话负例仍须单独验收。
- 协议 major=1、minor=0、schema=1、scope=`user-session`，消息 4 字节长度前缀、最大 65536 字节，请求 ID 与 15 秒内期限。宿主游戏管道最多 8 个连接，Agent 控制管道最多 4 个。Agent 上报原生创建提示经身份核对后的实例和显示快照，宿主以观察代数与 Desired State 送回绝对 HDR 请求。
- Agent 与宿主之间维持一条等待关闭的连接；断线不定期心跳。宿主不可用时每 5 秒尝试本地管道，连接成功停止重试，见 [ADR 0007](../adr/0007-game-process-window-hints.md)。UI 只在打开、用户刷新或规则操作时请求状态，不为 UI 设置后台刷新计时器。宿主向 Engine 注册状态来源后必须先提交完整快照，再送后续变化；否则 Engine 会拒绝增量状态。通知缺口后也重新提交快照。用户可在工作台“设置”页确认停止后台；若有被接管的游戏尚未退出，宿主拒绝停止以保留恢复能力。

## 当前限制

HDR任务状态读取现在按用户打开/刷新等现有请求，向Agent重新读取当前显示状态；不增加计时轮询。该只读刷新不更新Engine观察、不重试HDR、不改恢复基线或任务版本。UserEnabled=true但Active=false明确显示“设置为开启，当前实际未生效”，覆盖旧成功标题；当前值偏离最后确认值或读取失败分别显示变化/未知，不以缓存成功代替。成功回执仅证明动作当时读回，不能保证后续游戏/驱动切屏仍保持。2026-10-24现场原始标志0x71、activeColorMode=SDR，天国拯救崩溃模块nvwgf2umx.dll；现有证据未确定是谁令输出失效或崩溃根因，不据此强制重切HDR。

管理员 Agent 通过共享 Win32_ProcessStartTrace 检测无窗口进程，无 WITHIN、窗口提示降级或周期枚举；退出等待精确句柄。创建提示不保证早于游戏读取 HDR；极短进程可能在核对前已退出。订阅故障/队列溢出标 Unknown，不猜测退出或补发命令；源故障可重新打开后台建立基线。当前预览由 `Axiom.exe` 同账户 UAC 提权，不安装 Windows Service。设置的 `read-startup/set-startup` 管理当前用户最高权限交互登录任务，固定 `Axiom.exe --background`，不打开 UI、不保存密码；旧 Run 启用项迁移，关闭状态不新增登记。路径由宿主交付目录确定，要求四入口齐备；重复引导由当前会话用户 mutex 串行化。Windows 可延迟或禁用任务，搬动后更新位置，实际注销/重新登录未实测。后台入口失败写 `%USERPROFILE%\.axiom\startup-error.txt`。UI 退出后后台继续；进程挂起未启用。真实活动保存到 `activity.db`，可分页查看、清理七天前记录；旧内存结果无法补回。数值 CPU 验收按 [性能政策](performance.md)。

## 2026-10-24：显示模式与名称选择

HDR选择与Windows执行地址分离：单一设备名称保存为display-name选择，Agent每次执行解析到当前ConnectionPath，再由原API核对HDR预期状态并写入。旧路径只在当前型号唯一时解析，观察基线建立且无恢复控制时原地转换为名称目标；同名或旧型号多候选不猜测，已有游戏不补执行。Host与Agent共享HdrDisplayTargets，避免观察与执行选屏不一致。缺失连接、系统明确不支持、读取未知与开关未生效分别解释，不再笼统称不支持，也不立即用“检测到游戏”盖掉失败提示。

名称策略表示用户选择同名设备，不是序列号绑定；重名时按连接选择，名称改变需重选。它解决正常连接实例变化，不保证辨别名称相同且无法报告唯一身份的实体设备。[Windows设备实例ID](https://learn.microsoft.com/en-us/windows-hardware/drivers/install/device-instance-ids)由总线设备信息生成；[目标名称结构](https://learn.microsoft.com/en-us/windows/win32/api/wingdi/ns-wingdi-displayconfig_target_device_name)区分设备名称与连接路径。游戏模式本身的开关/规则影响不变，Wiki正文核对仍适用。
