## 环境

仓库为私有，main 是当前可用阶段的新起点。提交只包含源码、构建脚本、必要技术规范和合成测试数据；原机器的历史现场记录、个人配置、日志、截图及旧 Git 历史不上传。提交作者采用通用项目身份。

Codex Cloud 选择本仓库和 main 创建环境，安装命令为 `bash tools/cloud-setup.sh`，验证命令为 `bash tools/test-core.sh`。脚本使用 `$HOME/.dotnet`；Windows/PowerShell 可用 `pwsh -File tools/test-core.ps1`，两入口共用核心测试名单。Linux 不运行 WinUI 或原生 Windows 集成，不能把平台缺失当测试成功。

首次在设置 → Codex Cloud → Environments 创建私有环境，选择本仓库。可将以下内容交给环境设置对话：

> 读取 AGENTS.md 和 docs/development/cloud-workflow.md；运行 bash tools/cloud-setup.sh，再运行 bash tools/test-core.sh；仅准备环境，暂不开发功能。保留核心测试输出，Windows 构建使用仓库的 GitHub Actions。准备成功后等待所有者发布环境。

环境必须 Publish 后再开始开发任务。GitHub CLI 授权只用于 GitHub，不能代替 Codex 侧的仓库访问授权。若仓库没有出现在选择器中，在 GitHub 连接设置中授予此私有仓库访问权限。现有 Codex CLI 支持提交/查看云端任务，但没有创建环境命令。

GitHub Actions 的 Check source 在 Ubuntu/Windows 运行明确的核心套件，Windows 额外构建应用；Build Windows packages 手动生成便携和安装包。自动检查不启动用户后台，不使用个人规则，不自动发布 Release。

## 已确认方向与候选能力

2026-10-09 所有者明确调整方向：早期优先大量提出和开发实用检测能力、执行能力，由开发者主动发现 Windows 日常使用痛点并提出方案，不能只等待所有者逐条发明需求。上一版“首轮不扩展新能力、以收敛发布为主”的提案停止沿用。

核心目标是减少重复操作、打断和手动设置切换。以真实场景覆盖和可组合性衡量价值，能力数量不设固定配额。可靠性、低后台成本和清晰反馈是每项能力的交付要求，不能演变为长期只整理框架。

### 候选场景池（不代表已经实现）

| 日常场景 | 候选检测 | 候选动作 |
|---|---|---|
| 离开与返回电脑 | 锁屏、解锁、会话登录、睡眠恢复 | 静音/恢复、启动工具、发送提醒 |
| 耳机与音响切换 | 音频设备接入/移除、默认设备变化 | 切换播放/录音设备、设备或指定应用音量、麦克风静音 |
| 接电与移动使用 | 接电/拔电、电量跨阈值 | 切换电源方案、调整亮度、提醒 |
| 外接屏与桌面布局 | 显示器连接/断开、显示布局变化 | 窗口移至指定屏幕、位置/尺寸、最大化/最小化/置顶 |
| 专注、游戏和会议 | 前台应用变化、窗口出现/消失 | 配合现有程序/HDR能力，调节指定应用音量、管理窗口 |
| 不同网络环境 | 指定网络连接/断开、网络可用性变化 | 启动/关闭配套程序、提醒 |
| USB设备与外设 | 指定设备接入/移除 | 启动配套程序、打开目录、通知 |
| 定时事务 | 单次/周期时间、时间段限制 | 提醒、打开文件/目录/网址、运行已有动作 |
| 文件工作流 | 指定目录文件创建/变更，合并事件并判断就绪 | 按明确筛选移动/重命名文件；覆盖/删除另设明确策略 |
| 临时保持工作状态 | 指定程序、用户显式开启、必要条件组合 | 条件成立期间阻止休眠，结束后释放 |

候选须先核实 Windows 接口、权限、通知机制和验证条件。没有可靠系统事件来源时不能偷偷改为轮询；高成本或脆弱方案说明取舍后降序处理。音频、外设与显示等需要真实 Windows/硬件验证，云端编译通过只算部分完成。

### 首批建议（等待确认）

优先交付锁屏/解锁、睡眠恢复、前台应用变化、窗口出现、接电/拔电、单次/周期定时等检测，以及系统通知、打开文件/目录/网址、窗口定位/置顶等动作。先让新检测组合已有程序、窗口、托盘、HDR和快捷键能力；之后扩展音频、显示器与外设场景。最终顺序由收益、可行性和验收条件决定。

每轮由开发者自行提出候选，挑选高价值小场景，交付配置保存 → 检测 → 动作 → 结果/失败原因 → 暂停 → UI退出仍工作；随后继续下一项，无需所有者逐条催促。优先多选、应用内批量输入、按需事件订阅；只有场景确实需要时再补最小条件组合或顺序动作，不先铺大型流程编辑器。

临时设置须明确结束恢复、手动接管和冲突语义，不能简单延时写回旧值。示例规则供用户选择，不擅自启用会改变电脑的规则。每轮独立分支/提交，记录证据和下一项；仅在完成、实质阻塞或范围决策时请求所有者介入。
