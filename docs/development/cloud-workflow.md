# 云端开发与待确认目标

当前只配置开发环境和自动检查。以下目标是提案，所有者确认前不得自动启动长任务、定时任务或功能扩展。

## 环境

仓库为私有，main 是当前可用阶段的新起点。提交只包含源码、构建脚本、必要技术规范和合成测试数据；原机器的历史现场记录、个人配置、日志、截图及旧 Git 历史不上传。提交作者采用通用项目身份。

Codex Cloud 选择本仓库和 main 创建环境，安装命令为 `bash tools/cloud-setup.sh`，验证命令为 `bash tools/test-core.sh`。脚本使用 `$HOME/.dotnet`；Windows/PowerShell 可用 `pwsh -File tools/test-core.ps1`，两入口共用核心测试名单。Linux 不运行 WinUI 或原生 Windows 集成，不能把平台缺失当测试成功。

GitHub Actions 的 Check source 在 Ubuntu/Windows 运行明确的核心套件，Windows 额外构建应用；Build Windows packages 手动生成便携和安装包。自动检查不启动用户后台，不使用个人规则，不自动发布 Release。

## 候选目标（等待确认）

1. **第一版可靠性**：优先修复可复现的配置丢失、误执行、暂停/取消无效、后台重连和启动失败；每个修复有回归证据，已有能力正常工作。
2. **设置和故障说明**：让用户能看懂规则为何没有执行、快捷键为何登记失败、目标程序为何没找到；改进现有界面，不新增空功能页。
3. **分发完整性**：验证干净 Windows、升级保留配置、登录启动、安装卸载以及便携使用；构建结果可下载，硬件项目单列待验。
4. **后台资源控制**：只针对真实异常或已证实问题定位订阅泄漏、无界队列或无理由唤醒；保持事件驱动，不为优化而循环重构。

建议顺序为 1 → 3 → 2 → 4。每轮完成一个可验收改动，独立分支/提交，检查通过后记录证据和下一项。没有明确收益时结束，不为持续运行制造任务。

## 授权边界

目标确认后，可以自行实现、检查、修复及提出 PR。默认不合并主分支、不公开仓库、不发布 Release、不新增付费服务、不引入外部插件市场或任意命令执行能力。目标范围变更和真实设备验证需要所有者决定。云端产物不能直接覆盖正在使用的本机版本。

公开流程依据：[Codex Cloud 环境](https://learn.chatgpt.com/docs/environments/cloud-environments)、[长期目标](https://learn.chatgpt.com/docs/long-running-work)。环境必须在账户侧实际创建并验证，仓库包含脚本不等于已经连入云端。
