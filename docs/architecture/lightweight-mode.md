# Performance / Lightweight Mode

Performance Mode、Lightweight Mode、性能模式、轻量模式指同一个模式，不是两个功能。正常模式也遵守 CPU-first；轻量模式进一步缩减允许推迟或暂停的工作。默认正常模式；是否自动根据游戏状态切换不在第一阶段范围，未来须独立规则与明确授权。

## 核心 contract

- 模式有 RequestedMode、EffectiveMode、generation、transition status、reason 和可解释 exceptions；变更只经 Engine。
- 每条启用规则有 `KeepInLightweight`（新规则保守默认 true）及声明的最大响应/新鲜度要求。只有用户明确允许暂停的规则才可设 false。
- priority 与 KeepInLightweight 是不同维度：低 priority 且可暂停的自动化受抑制；低 priority 但明确保留的核心规则仍运行。不得仅凭优先级自动停掉用户保留规则。
- 由保留规则、手动接管、权限/关键控制和在途必要收敛计算传递依赖闭包。闭包中的 Provider/观察器不能停；共享观察器只在所有必要依赖释放后停。
- 无法满足保留规则 contract 时不得静默降精度或显示成功：模式切换保留所需资源，并报告“轻量已启用，存在必要例外”；如果连正确性都无法维持，显示受阻/失败并保留可用旧模式。

## 正常与轻量模式

| 行为 | 正常 | 轻量 |
|---|---|---|
| 核心规则/权限/接管 | 完整保证 | 相同保证 |
| 观察器 | 按有效依赖激活 | 仅保留必要闭包，停非必要观察器 |
| Provider | 按需，闲置释放 | 禁用无必要依赖的非必要 Provider |
| 自动化 | 全部启用规则 | 暂停获准暂停的低优先级/非必要规则；保留规则不受此抑制 |
| 非关键日志/统计 | 有界采样与批量写入 | 暂停；不为统计维持 timer |
| 关键审计/错误 | 保留且限流 | 保留且限流，不破坏耐久确认 |
| 诊断采样 | 按需有时限 | 默认关闭持续采样；显式诊断降低频率并有时限 |
| 刷新/验证 | 按 contract deadline | 仅在声明容忍范围内延长；不能错过保留规则时限 |
| UI | 可完全退出 | 同样可完全退出，后台不依赖 UI |
| Web/Remote | 默认不启动 | 强制关闭，除非用户显式 KeepRemoteInLightweight；V1 未实现 |

Remote 保留例外须可见，不能由外部客户端自行打开；即使显式保留也要走现有 Capability/鉴权。若未来某条保留规则确实依赖远程输入，未获保持远程授权时拒绝这项不兼容切换并解释，不能偷开远程或偷停规则。

## 切换过程

Engine 串行接受模式变更，按配置 revision 计算计划，验证必要依赖可继续提供保证；取消尚未执行的可暂停 Intent/Command，撤销其调度，不重放遗漏命令。不可取消的在途操作等待有界完成并重新观测，不能宣称已撤销其副作用。生效状态须等待资源释放/保留结果确认；失败暴露具体残留资源。

退出轻量模式：按需恢复订阅、获取可能缺失的状态快照，重新评估相关规则，不回放暂停期间的 Command；Desired State 以最新配置重新收敛，不复用过期 generation。暂停规则若原来是唯一目标，默认释放管理并保留当前物理状态，遵守 state-model。

## 不可破坏的保证与验收

身份/权限、Override、冲突裁决、Command 不重复、已保留规则的时序/新鲜度保证完全不变。Unknown 不可当作 false；不能为省电放宽用户指定时间约束。模式切换不产生双重订阅、泄漏定时器或重放命令。

测试：共享 Provider 一条保留一条暂停；低 priority 但保留；中途切换遇在途执行；Agent 掉线/重启；频繁切换；没有可削减工作；远程例外。使用相同保留规则事件轨迹对比两模式，核心决策必须一致；暂停部分允许的差异须解释。量化基准统一见 [V1 provisional targets](../development/performance.md)。
