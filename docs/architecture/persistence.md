# SQLite 与恢复 contract

Service 拥有 SQLite 写入权。UI/Agent 通过 Engine 请求读取/变更；Engine 依赖存储 port，不引用 SQLite 包。0006 开发宿主已实现**不可执行规则草稿**的单写入 SQLite 子集，具体路径、schema、迁移及限制见 [草稿 contract](../development/rule-draft-persistence-contracts.md)。0008 已保存可执行游戏规则，见 [预览 contract](../development/game-hdr-preview-contracts.md)；通用持久意图、接管与命令回执仍待后续。

## 保存与不保存

保存配置/规则版本、用户授权设置、持久 Desired 意图、手动接管策略、模式配置、必要命令回执/去重信息、有限关键审计。Observed 缓存最多是启动提示，重启后必须标为 Unknown 并重新观测。瞬时 Event Bus 不等同于持久事件日志，不默认保存全部系统事件。

配置更新事务性提交后才能回报已保存；若提交失败，不对外假装配置已生效。提交与内存发布的恢复顺序必须可重放并以配置 revision 对账。命令受理记录和执行回执需要明确持久化点，但外部副作用不能与 SQLite 构成原子事务；不承诺跨崩溃 exactly-once。

## 日志与 CPU

当前活动记录由 Engine 的 `IActivityHistory` port 接入宿主，保存到 `%USERPROFILE%\.axiom\preview-rule-drafts\activity.db`，独立于规则和快捷键数据库。只记录有意义的后台生命周期、配置变更、检测、执行/恢复、冲突和异常；不持久化每次查询或所有原始系统通知。`ActivityJournal` 有界事件队列、单消费者、最多 64 条一批事务写入，无空闲刷新或清理计时器；规则运行锁内只入队，不进行日志磁盘 I/O。队列溢出/写入失败在活动页说明未保存记录，日志故障不停止自动化。

活动保留至用户清理，不静默截断历史或每轮开发自动清库。按递增 ID 游标分页，UI 根据当前窗口可视空间请求合适数量（后台允许 1–64 条），避免新写入挤动历史页和加载全库；当前 UI 可翻页访问全部保留活动。清理时由后台计算 UTC 当前时刻减七天，删除严格早于该期限的行；不接受客户端自选日期、清理全部或直接写日志。退出后台排空已接收记录，重开读回；突然终止可能损失尚未提交的队列记录，不宣称断电零丢失。

普通诊断批量写入、有界缓冲、大小/时间上限和保留策略；缓冲为空不周期唤醒。关键配置、接管、权限变更使用必要的耐久写入，不能为了“批量”延迟确认其生效。轻量模式暂停非关键统计/日志；安全审计和关键错误保留并限流去重，不无限淹没磁盘。

一般配置的 WAL、同步等级、checkpoint 阈值在实测与耐久要求后选择；不预先强推高频 flush，也不能关掉耐久性来美化性能。0006 低频草稿预览暂用 rollback journal、`synchronous=FULL` 和 2 秒 busy timeout，未做数值性能验收。维护在有需求和允许的时间窗执行，不以每秒定时清理全库。

## 失败与迁移

单写入协调有界 busy 等待；磁盘满、锁超时、损坏必须返回明确错误。无法可靠记录需要耐久保障的变更时拒绝该变更，现有已确认配置能否继续运行须显示降级状态。用户于 2026-10-01 明确要求直接更新当前状态、不自动备份、不启用 EFS；迁移在原库事务提交并验证版本和完整性，只有明确要求时才制作备份。未知较新版本不自动降级，旧二进制不能读取较新 schema。数据库回滚与代码回滚不是同一件事；没有备份时不承诺恢复旧状态。

当前 Windows 预览使用 `%USERPROFILE%\.axiom` 作为单一用户数据根，由 `AxiomUserData.Root` 统一提供。规则与快捷键仍只由宿主写入，主题是 UI 外观偏好。避开 AppData 是为处理打包开发工具的文件重定向；不能只核对逻辑路径，启动一致性验收必须核对实际文件标识。

2026-10-04 新会话命令插件任务使用同目录 `tasks.db` 的 `automation_tasks(id, version, configuration)`；参数存为版本化 `AutomationTask` JSON，不为每个能力加表或列。旧 `game-hdr.db` 保留 HDR 生命周期数据，无迁移/预设重播/自动备份。乐观版本在事务中核对并递增，提交后才确认；暂停配置持久化。较新数据库版本拒绝打开，不降级覆盖。模块暂不可用的配置仍保留并记录问题，不静默删任务或改成预设。

Override 带 UTC expiry 可持久化；进程内等待使用单调时钟；恢复时用明确到期策略重算，时钟异常保守保留接管并显示需确认。不得保存未加密的秘密到普通配置/日志；机密存储机制在远程能力计划中另定。

2026-10-05 进程组使用同目录 `process-groups.db`，表 `process_groups(id, version, name, entries)`，entries 为程序名/显示名 JSON；Host `SteamToolManager` 共享协调锁单写入，乐观版本在事务中校验、递增并提交。最多 32 组、每组 128、合计 512 条，写入前另核对序列化大小以符合 256 KiB IPC 帧；同名进程合并，同名组拒绝。schema 原地事务升级到 2，新增单例 `steam_tool` 保存开关、排除项、自动组 ID、最近完整名单/警告及扫描/成功时间。组与工具状态同事务提交；配置有独立乐观版本。未知版本/损坏拒绝，无预设播种、自动备份或 EFS；旧 schema 1 二进制不能回读新版。

Steam 工具默认关闭；开启立即检查，之后每次后台启动检查一次，关闭时后台启动不读取 Steam 元数据，保留已有组和结果。最近完整结果持久化供设置查看，发现缓存仍在内存，文件通知只标脏，无周期扫描。完整结果扣除长期排除项后原子替换固定“本机上的Steam游戏”，未变化不增加组版本；安装路径/库不可用、元数据不完整、扫描异常及容量超限保留原组并解释，不以部分/空失败结果删除名单。关闭扫描中的开关后不得继续导出。组是配置选择来源，规则不存组引用，组改变不自动修改既有规则。
